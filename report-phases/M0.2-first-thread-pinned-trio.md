# M0.2 — First Thread + pinned trio

**Status:** ✅ Done (2026-09-02) · **Commits:** `9a7272a` (housekeeping), `4ed8294` (M0.2) · **Branch:** `main`

## What this phase delivered

The Electron renderer now displays a real chat interface: one assistant-ui `Thread` running on a
hello-world local runtime. Sending a message streams a fixed echo/greeting reply word-by-word —
entirely in the renderer, with no IPC, no model provider, and no network. This proves the UI layer
of the chat pipeline (docs/02 §2.1, left side) before M0.3 wires the real IPC transport.

### How the trio was resolved

- The rule was "the bridge package dictates the `ai` version — downgrade `ai` first if they clash".
  Reality on the registry: **`ai` v7 already exists**, and the newest bridge (`@assistant-ui/react-ai-sdk@1.4.8`)
  hard-depends on `@assistant-ui/ai-sdk@0.0.3` → `ai ^7.0.77`, with no `ai` peer range left to satisfy by downgrade.
- The last bridge release line targeting AI SDK v5 is **1.1.21** (`ai ^5.0.116`, `@ai-sdk/react ^2.0.118`).
  1.2.0+ jumped to ai v6; 1.3.41+ to ai v7.
- 1.1.21 peers on `@assistant-ui/react ^0.11.56`, which pins assistant-ui to the **0.11.x line** —
  a downgrade from the latest 0.15.17. Accepted: STACK.md mandates `ai` v5 and npm overrides are banned.

### Two landmines found and avoided

1. **`@assistant-ui/react` 0.11.57/0.11.58 crash `useLocalRuntime`** — 0.11.57 introduced an unbound
   method call (`__internal_setGetInitializePromise` extracted from the runtime core and invoked
   without `this`) inside `RemoteThreadListHookInstanceManager`; the renderer throws
   `Cannot set properties of undefined (setting '_getInitializePromise')` in `_InnerActiveThreadProvider`
   and the tree unmounts. **0.11.56 is pinned** (still within the peer range, and the version the
   bridge line was developed against). Do not bump within 0.11.x past it.
2. **assistant-ui's current docs no longer document the local runtime** — the site now documents the
   v7-era `@assistant-ui/ai-sdk` package and shadcn component registry. The APIs used here were
   verified against the published 0.11.56 `.d.ts` files plus the current "Model Adapters" API reference.

## Implementation notes

### Renderer (`app/src/renderer/src/App.tsx`)

- `useLocalRuntime(helloWorldAdapter)` wrapped in `AssistantRuntimeProvider`.
- `helloWorldAdapter: ChatModelAdapter` — an async generator that echoes the last user message back
  inside a fixed greeting, yielding **cumulative `content` snapshots** word-by-word (≈40 ms), and
  returns early when `abortSignal.aborted`. Replaced wholesale by the real IPC transport in M0.3.
- Thread composed from primitives only:
  `ThreadPrimitive.Root` → `Viewport` (+ `If empty` welcome screen + `Messages`) → `ViewportFooter` →
  `ComposerPrimitive.Root` (`Input` + `Send`). `ComposerPrimitive.Send` auto-disables while the
  composer is empty or a run is in flight.
- Messages: `MessagePrimitive.Root` + `MessagePrimitive.Parts` with a `Text` part component per role.

### Verified API shapes (0.11.56)

- `ChatModelAdapter.run(options: ChatModelRunOptions): Promise<ChatModelRunResult> | AsyncGenerator<ChatModelRunResult, void>`
- `ChatModelRunOptions`: `messages: readonly ThreadMessage[]`, `runConfig`, `abortSignal`, `context`
  (⚠ renamed from `config` — the old field remains, deprecated).
- `ChatModelRunResult`: `{ content?: readonly ThreadAssistantMessagePart[], status?, metadata? }`.
- `ThreadPrimitive.Messages` requires `components={{ UserMessage, AssistantMessage }}`.
- `MessagePrimitive.Parts` (0.11 renamed from `Content`); text part component receives `text`.
- `ComposerPrimitive.If` filters are `editing`/`dictation` only — there is no `running` filter.
- `ThreadMessage.content` is always a part array in 0.11 (no plain-string variant).

### Styling

Minimal chat shell in the existing `main.css` (built on `base.css` variables): full-viewport column,
scrollable message viewport with user/assistant bubbles, bottom composer row (auto-growing textarea +
Send button). **No tailwind, no shadcn** — those arrive with a later phase per the plan.

## What M0.3 must know

- Swap point: replace `useLocalRuntime(helloWorldAdapter)` with `useChatRuntime({ chat })` from
  `@assistant-ui/react-ai-sdk@1.1.21` + `useChat({ transport })` from `@ai-sdk/react@2.0.253`, where
  the transport is our custom IPC `ChatTransport<UIMessage>` (docs/02 §2.1). The hello-world adapter
  and its comment are deleted then.
- Re-verify the 1.1.21 bridge's exports against its `.d.ts` at M0.3 time — the current assistant-ui
  docs describe the v7-era `@assistant-ui/ai-sdk` package, which is *not* ours.
- AI SDK v5's `ChatTransport` shape (`sendMessages`, `reconnectToStream`) is the v5 API — not v4's
  fetch-handler style.
- Do not upgrade `@assistant-ui/react` within 0.11.x past 0.11.56 (crash bug above); any move past
  0.11.x requires moving off `ai` v5 — a STACK.md decision, not a dependency bump.
